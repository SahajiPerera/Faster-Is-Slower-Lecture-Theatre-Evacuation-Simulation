About / How to use

150 people (10 rows, two aisles, one exit door in the front wall) leave a lecture theatre. Each person is a disc driven toward the nearest aisle and then to the exit, and is pushed by neighbours and walls (social repulsion, body compression and sliding friction). Integration is velocity Verlet. Circle colour shows speed.

  1. Press Start to watch one run. Pause and Reset work as usual. Changing a parameter resets the run.
  2. Try the presets, or change the desired speed, door width and pillar yourself.
  3. Press Run batch for the mean evacuation time with a 95% confidence interval over several seeds. Tick Show animation during batch to watch each run as it is computed (slightly slower).

Try this: run a batch at v0 = 3 and another at v0 = 7 with a 1.2 m door. The faster crowd needs longer (faster-is-slower). Then widen the door to 2.0 m and the effect disappears.

Notebook reference checks (door 1.2 m, no pillar; values from the notebook's full run, FULL_RUN = True, 10 seeds; the quick run uses fewer seeds, so its numbers differ):

  • v0 = 3 m/s: 64.3 s (95% CI +/- 2.0 s). A batch of 10 runs here must agree within +/- 5 s.
  • v0 = 7 m/s: 81.9 s (95% CI +/- 7.2 s). A batch of 10 runs here must agree within +/- 10 s, because both intervals are wider at this speed. These runs use dt = 0.0005 s and are much slower than the 3 m/s runs: on the author's laptop a run took about 30 s (measured over 2 runs), so a batch of 10 takes about 5 minutes (an earlier 10-run batch gave 78.2 s, PASS). Keep the tab visible and in front while it runs: a hidden tab is throttled by the browser and can take several times longer. For a quick check use fewer runs (for example 3 to 5), which gives a wider interval. The elapsed time of each batch is shown in the results box.

A PASS/FAIL badge appears at those settings. Tolerances are roughly the notebook interval plus the demo's own interval.

Limitations: 2D plan view, round bodies, same desired speed for everybody. JavaScript's random generator differs from NumPy's, so a single seed will not match the notebook, only the statistics do. Speeds above 5 m/s use dt = 0.0005 s and run roughly 2 to 3 times more slowly (about 30 s per run at 7 m/s against about 11 s at 3 m/s on the author's laptop).

Numerical safeguards: as in the notebook, a run is marked invalid and excluded from batch statistics if a person ends up outside the room (tunnelling through a wall, a risk at very high desired speeds with too large a time step). The demo finds neighbours by checking every pair, O(N2), whereas the notebook uses cell lists; with only 150 people the forces and results are identical, the notebook version is just faster for large crowds.
